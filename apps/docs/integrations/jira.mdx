Roomote uses Atlassian's official **MCP v2** server for Jira. Agents can
search, read, create, edit, transition, and comment on work items, subject to
the permissions of the connected Atlassian account.

## Connect Jira

1. As a Roomote deployment admin, open **Settings > Integrations**.
2. Add or enable **Jira**, then authorize Roomote through Atlassian's OAuth
   consent flow.
3. Grant access to the correct Atlassian site and confirm the issue-level
   permissions.
4. Open **Manage tools** to check the available tools and disable individual
   operations that Roomote agents should not use.

The connection is deployment-scoped, so authorized Roomote agents can use it
for both interactive and unattended tasks. Jira access is limited by the
connected account's Atlassian project permissions and the enabled MCP tools.

Roomote requests Jira **read**, **search**, and **write** permissions. It does
not request Jira deletion or project administration permissions.

## Migrating from Jira MCP v1

The previous Jira integration used Atlassian's v1 MCP server. **v2 uses a
different OAuth resource; existing v1 credentials do not carry over.** After
upgrading Roomote, reconnect Jira in **Settings > Integrations** and complete
Atlassian consent again. There is no need to add a second Jira integration.

Roomote uses the [official v2 MCP endpoint with a flat tool catalog](https://support.atlassian.com/atlassian-ai-gateway/docs/how-to-upgrade-from-atlassian-mcp-v1-to-atlassian-mcp-v2/)
so that per-tool enablement controls work through its shared MCP proxy.

## Verify it works

1. Open **Manage tools** and confirm issue operations such as
   `getJiraIssue`, `searchJiraIssuesUsingJql`, and `createJiraIssue` are
   available to the connected account.
2. Ask a Roomote agent to retrieve a known issue, for example:
   "Read issue PROJECT-123 and summarize the acceptance criteria."
3. Create a test issue in a project where the connected account has permission,
   then ask the agent to update or comment on it.
4. Run a similar request from a scheduled agent to verify unattended access.

If tools are missing, check the consented scopes, Atlassian organization MCP
permissions, and the connected account's Jira project permissions. An error
about a missing MCP session can also indicate that the deployment is still
running an older version of Roomote.

For details, see [Atlassian's MCP setup guide](https://support.atlassian.com/atlassian-ai-gateway/docs/get-started-with-the-atlassian-remote-mcp-server/).
